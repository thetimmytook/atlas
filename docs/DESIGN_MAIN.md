# Atlas — основная навигация проектирования

## Как читать

Начинать с этого файла, затем открывать только относящиеся к текущей задаче темы.
Пользователь ведёт проектирование, ассистент проверяет и советует. Реализация ещё
не начата. Обсуждаем крупные блоки, конкретные идеи сохраняем как решения или
открытые decision points. Не превращать примеры API в утверждённые сигнатуры.
В ответах с несколькими темами использовать сквозную нумерацию пунктов, чтобы
пользователь мог ссылаться на номер без копирования текста. Нумерация начинается
с 1 после этого уточнения; продолжать между ответами, не полагаться на HTML-якоря.

## Актуальная основа

- Desktop/mobile, просмотр карт; редактор — отдельный потребитель библиотеки.
- Serializable JSON и runtime-экземпляры с поведением разделены.
- Координаты x вправо, y вниз, z вверх. SVG первым; настоящее 3D — направление развития.
- Общий objects; слои выбирают объекты и отсекают их через clip. Отдельного level нет.
- stackIndex задаёт композицию; это не высота z и не замена глубины в 3D.
- Маршрут содержит lines, без промежуточных segments и общего route.points.
  Связность поддерживается поведением маршрута.
- Материалы именованные, наследование явное. Специфичность выбирает один материал,
  не смешивает автоматически материалы разных уровней. Термины Meta/styles устарели.
- Регистрация свойств/поведений в изолированной конфигурации до создания карты.
- label — явный объект данных; runtime-подпись — часть владельца с поведением.
- Синхронный вложенный batch откладывает только отрисовку, без отката изменений.
- Строгая загрузка данных/ресурсов; новая карта заменяет текущую после успешной подготовки.
- Runtime хранит логику; renderer рисует, клипует и определяет цель взаимодействия.
- Framework-адаптеры отдельные. Пользовательское состояние хранит приложение.
- Ресурсы описываются один раз в реестре карты, используются по ID;
  предусмотрен подключаемый загрузчик приложения.

## Где остановились

Первый проход архитектуры достаточен для перехода к проверке прототипом.
Пользователь согласовал объём и цель прототипа: проверить идею, выявить ограничения,
уточнить следующие шаги. Не стремимся закрыть все вопросы до реализации.
Последние пункты ответа ассистента — 3 (объём) и 4 (результат), оба подтверждены;
следующую нумерацию продолжать с 5.
Согласованы граница runtime/renderer и основа жизненного цикла Web Component.
Resize меняет размер viewport, сохраняя центр и zoom без повторного вписывания.
Приняты реестр ресурсов, подключаемый загрузчик и состав документа карты;
исполняемая конфигурация остаётся вне JSON. Подтверждены современные браузеры,
mouse/touch и базовая доступность; обработчики клавиатуры — открытый вопрос.
Согласован ориентир прототипа 3000/5000 объектов. Исследованы все конфигурации карт
tarkov.dev, данные и обзор основных экранов; находки сохранены отдельно.
Оба сценария просмотра здания полезны, но UI, Escape/«Назад» принадлежат приложению.
Механизмы нескольких карт/viewport и группы слоёв остаются decision points.
Default layer связываем со stackIndex; адаптивность и экструзия зон отмечены
для последующего проектирования.

## Крупные оставшиеся блоки

1. Завершить жизненный цикл, публичный API и согласованный контракт событий.
2. Свести минимальные контракты материалов/свойств/label, сохранив decision points.
3. Уточнить ресурсы и состав экспорта Map JSON (schemaVersion принят).
4. Требования к браузерам, доступности, вводу и ожидаемому объёму данных.
5. Объём прототипа согласован; уточнять измеримые критерии и ограничения в ходе проверки.
6. Собрать чистую спецификацию и вынести исторические варианты из рабочих контрактов.
